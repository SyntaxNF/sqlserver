# SQL Server 2025 command coverage

Checked: 2026-09-30. Baseline: SQL Server 2025 (17.x), compatibility level 170, GA Database Engine statements. This replaces the initial 29-file MVP inventory.

## Measured scope

- **302 SNF files**, 273 added to the original 29; files organize statements, not an artificial command-count target
- **377 inventory rows**: 265 supported statement shapes, 76 partial shapes, 36 explicit exclusions/non-statements
- 341 modeled rows map to files; multiple SET options/variants can share a file. Do not call this number distinct T-SQL commands
- **454 official source pages reconciled** in [source-catalog.json](source-catalog.json): every Markdown page in the official statements and DBCC directories, plus the enumerated standalone language/control/cursor/transaction/query pages
- No unreconciled page in that bounded source catalogue. This is **catalogue accounting, not full grammar completion**. Subreferences, product exclusions and non-statements are visible rather than silently discarded

## Status definitions

- **supported**: the stated statement shape/branches are structured with ordinary typed identifier/literal leaves. This is not a promise of all legal permutations, semantic validation, platform availability, parser compatibility or successful database execution
- **partial**: a known applicable branch, complex input grammar or option catalogue remains unexpanded; the Notes column and linked contracts are part of the definition
- **not-applicable**: other-product syntax, preview outside this GA baseline, an absent standalone command or a separately classified non-statement. This never means an existing SQL Server feature was proven unavailable merely because it lacks a file

[Machine-readable command inventory](inventory.json) and [upstream page/sha mapping](source-catalog.json) make the denominator auditable. The source snapshot is the MicrosoftDocs/sql-docs live directory listing read on the check date; individual Git blob SHAs identify the observed page revision. Pages can change after this date. Expressions, built-in function/type/operator catalogues, system stored procedure signatures, SQLCMD/GO and undocumented DBCC are outside this command-inventory denominator. EXECUTE represents calls without pretending to enumerate every system procedure.

## Applicable work still incomplete

1. Query expressions, FROM rowset/TVF/JSON/XML/PIVOT subgrammars, window-frame and full set/grouping combinations, DML hints/UDT/remote and graph-expression variants
2. Memory-optimized/FileTable creation and some ALTER TABLE/index/constraint/storage branches; scalar type/function catalogues remain typed opaque inputs
3. Module bodies and native statement restrictions, full permission/audit/XE event/predicate catalogs, provider-specific HSM/PFX and external connector/package option semantics
4. Database scoped/SET options and HA/backup/restore runtime combinations noted per row; not every valid permutation or every CU-specific capability is represented
5. Consumer directive binding, reference resolution, semantic checks, positive/negative examples and opt-in parser/engine/Studio validation

These are genuine remaining partial grammar tasks, not hidden behind the file count. Native JSON and JSON INDEX are currently GA and included where applicable. CREATE VECTOR INDEX, half-precision vectors, fuzzy matching, change event streaming and local ONNX runtime preview are excluded. Azure Arc-enabled engine identities and ordinary external Azure/S3 destinations are not automatically Azure-SQL-only features.

## Known official-source inconsistencies

- Selective XML ALTER syntax summary shows WITH options alongside FOR, but Arguments prohibits combining them; FOR branch follows the restriction
- Clustered COLUMNSTORE ORDER/WITH ordering differs between SQL Server syntax summary and examples; definition follows examples G/H and remains partial pending opt-in engine verification
- JSON INDEX syntax summary lists DATA_COMPRESSION, but Limitations says unsupported; that option is omitted
- ALTER EXTERNAL LANGUAGE syntax mentions PARAMETERS/ENVIRONMENT_VARIABLES while Remarks says unsupported; ALTER omits them, CREATE retains its separately documented options
- DBCC SHOW_STATISTICS STATS_STREAM is explicitly unsupported/informational-only and is omitted, as in CREATE/UPDATE STATISTICS
