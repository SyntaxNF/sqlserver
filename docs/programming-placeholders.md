# Programming and session grammar contracts

Target SQL Server 2025 Database Engine GA. This is statement-shape coverage, not a SQL validator. The inventory reports `supported` for a complete modeled statement shell, not database-tested support; `partial` means nested grammar/branches remain opaque. No parser, engine, tests or Studio execution has been performed.

## Names and scalars

`parameter`, `variable`, `return_variable`, `module_variable`, `cursor_variable`, `string_variable`, `message_variable`, `binary_variable` include the leading @. Do not add a second @. `name` is the statement's primary name with only its permitted qualification; DDL/logon trigger names are not schema-qualified. `assembly`, `class_name`, `method_name`, `member_name`, `owner`, `securable`, `module_name`, `object_name`, `table_type`, `linked_server`, `data_source`, `cursor_name`, `label` are context-typed identifiers. Dotted CLR class names need identifier quoting. `file_name` is the SQL string/identifier form prescribed by assembly syntax, not an unescaped filesystem path.

`data_type` and `base_type` must obey the particular module/type/variable position. `default_value` is a legal parameter default, generally a constant or NULL, not an arbitrary SQL expression. `argument_value`/`argument` are allowed EXECUTE/RAISERROR arguments, not arbitrary SELECT expressions. `value_expression`, `boolean_expression`, `integer_expression`, `string_expression`, `computed_expression` and `default_expression` have position-specific restrictions. Numeric `*_value` placeholders enforce official ranges and whether a variable is permitted. RAISERROR severity/state, THROW number/state and message size require validation.

`sql_text`, `user_name`, `principal_name`, `language` and other quoted lowercase placeholders are string contents: escape embedded apostrophes and retain the quotes generated by SNF. Uppercase strings such as 'ENTRY' are fixed literals. Dynamic SQL is not parsed by the SNF parser and cannot be assumed safe. Binary placeholders distinguish literal/variable-only SET CONTEXT_INFO from assembly expressions; CONTEXT_INFO disallows NULL and arbitrary expressions and is limited to 128 bytes.

## Nested statement contracts

`statement_block` is one complete statement or a matched BEGIN/END block; `sql_statement_list` is an appropriately delimited list of statements. Neither is a raw arbitrary suffix. Resolve nested statements using the engine grammar and permitted module context. UDF bodies cannot contain arbitrary side effects; native ATOMIC bodies have their own restricted statement set. Body statement delimiters are preserved by the consumer; do not insert batch GO into a module. DECLARE scope, BREAK/CONTINUE loop scope, RETURN procedure/function context, GOTO labels and TRY/CATCH adjacency and nesting require validation. THROW's preceding statement must end in a semicolon; argumentless THROW requires a CATCH block.

`query_statement` binds to SELECT with its contextual exclusions: no INTO/FOR BROWSE in cursors, UDF return restrictions, no INTO/OPTION/temp objects for views. CREATE/ALTER VIEW CHECK OPTION and indexed views exclude OFFSET/FETCH. `receive_statement` and `get_conversation_group_statement` in WAITFOR are Service Broker statements, not arbitrary statements.

`table_element_definition` in function returns, `table_type_element_definition`, `memory_table_type_element_definition` and `table_variable_element_definition` are **local structured definitions**, each for its specific context. They do not import CREATE TABLE blindly: no named/foreign-key constraints in UDF returns/table variables, distinct memory-optimized key/index shapes, and CLR result columns restricted to names/types. The function/DECLARE templates include common columns and constraints; DECLARE inline/table indexes and full legacy storage/index-option variations remain uncovered. Type/key/NULL/default/computed-column combinations are semantic checks, not independent unrestricted choices.

`ddl_event` is an event or event-group name allowed for the trigger scope, not a SQL statement. DML event lists must not repeat events. Trigger cases structurally separate T-SQL/CLR and DML/database-DDL/server-DDL/logon scope. CLR cases exclude ENCRYPTION. DML execution context may use CALLER/SELF/OWNER/user; database DDL excludes OWNER and uses a database user; server DDL/logon excludes OWNER and uses a server login. A view uses INSTEAD OF. WITH APPEND is omitted from the 2025 baseline: the official CREATE TRIGGER argument scopes it to SQL Server 2008/2008 R2, requires FOR, and excludes CLR. CREATE OR ALTER and ALTER cannot arbitrarily convert module categories.

## Native, CLR and session restrictions

Native modules require their prescribed NATIVE_COMPILATION, SCHEMABINDING and ATOMIC settings; execution-context requirements differ between native procedures, functions and triggers. LANGUAGE and TRANSACTION ISOLATION LEVEL must appear once in ATOMIC options; no duplicates/conflicts. CLR execution and memory-optimized/native features have edition, OS, deployment and configuration requirements. Their inclusion records SQL Server engine syntax, not a promise of identical Windows/Linux support. `assembly_path_expression`, `file_path_expression`, `binary_expression`, `xml_schema_expression` are typed inputs with official file, binary, XSD, signature, dependency and permission constraints. UNCHECKED DATA and unsafe assemblies are represented without a safety-policy filter; consumers own authorization.

SET values are not uniformly expressions: DATEFORMAT/LANGUAGE accept documented tokens/string or variables; DATEFIRST is 1..7; DEADLOCK_PRIORITY -10..10 or its named levels; LOCK_TIMEOUT includes -1; ROWCOUNT/TEXTSIZE/cost have their own bounds. Legacy OFF settings can be deprecated or forced by engine behavior. SHOWPLAN options require their documented batch boundaries; STATISTICS and boolean-list settings differ. The inventory explicitly excludes SET RECOMMENDATIONS, SET RESULT_SET_CACHING and SET TIME ZONE from SQL Server scope. SETUSER remains deprecated SQL Server syntax, not advice to use it.

No ALTER TYPE, ALTER AGGREGATE, ALTER DEFAULT or ALTER RULE command exists; recreate the object as allowed by dependency and binding constraints. ALTER AUTHORIZATION is separate from these objects' definition grammar.

Trigger scope source: https://learn.microsoft.com/en-us/sql/t-sql/statements/execute-as-clause-transact-sql?view=sql-server-ver17 . Native options retain permutation flexibility in SNF; consumer must enforce the required LANGUAGE/isolation pair exactly once, not treat every item as optional.
