# Relational, indexing and external-object contracts

Scope note: the contexts and SQL restrictions below are reference information, not mandatory checks that an SNF generator must implement. Free expressions, bodies and reusable queries are legitimate inputs. The database or an optional consumer validation layer can enforce semantic rules; templates do not duplicate whole statements to encode compatibility matrices.

These files model SQL Server 2025 (17.x) GA statement shapes. `supported` in the inventory means the stated syntax shape is represented, not that SQL Server or the SNF parser has executed it. Scalar leaves remain typed inputs. `partial` means important branches or composite grammar nodes remain unexpanded.

## Queries and DML

- `query_statement` is a reusable or freely supplied SELECT statement. `query_specification` is one SELECT operand without top-level set operators, ORDER BY, FOR or OPTION; a parenthesized operand binds through `query_statement`. Set-operation cardinality, column types, precedence (INTERSECT before UNION/EXCEPT), top-level ORDER BY aliases, INTO placement and forbidden FOR BROWSE combinations are database semantics rather than template checks. SELECT and SET_OPERATION share an ORDER BY/OFFSET/FETCH tail; other partial scope remains explicit.
- `window_frame_clause` is the restricted ROWS/RANGE frame grammar, not arbitrary text; frame endpoints, ordering and named-window inheritance rules require validation. WINDOW requires compatibility level 160 or later; this baseline is 170.
- `table_hint` and `query_hint` are locally structured SELECT nodes; each position has its own legal subset, exclusions and conflicts. USE HINT names are not arbitrary future/preview feature approval. Preview FORCE_ANN_ONLY, cloud-only FOR TIMESTAMP and scale-out-specific hints are not included. Other DML files do not automatically import SELECT hints.
- `from_expression` is recursive local SELECT structure; UPDATE/DELETE keep opaque FROM sources. OPENJSON/OPENROWSET/TVF/OPENXML, PIVOT/UNPIVOT and join hints remain unexpanded. `system_time_clause` requires temporal tables, typed literals or variables, not arbitrary correlated expressions.
- GROUP BY grouping sets are structured only to the represented subset; nested grouping-set combinations and legacy WITH CUBE/ROLLUP variations remain partial. Expressions have their normal aggregate/window/subquery restrictions. JSON/XML serialization modes must obey query-context constraints.
- INSERT EXEC's `execute_statement` binds to EXECUTE and has no OUTPUT; result-set schemas must match, INSERT EXEC nesting and module restrictions are engine checks. Existing DML still omits several remote/hint/UDT/variable assignment branches.
- MERGE `merge_target`, `merge_source`, `merge_hint`, `set_clause` and `query_hint` are bounded opaque composite inputs for their exact official grammar positions. Source aliases, target updatability, action-column availability, TOP semantics and match cardinality need semantic validation. At least one WHEN is required; order is MATCHED, BY TARGET, BY SOURCE. At most two MATCHED and two BY SOURCE clauses are permitted; paired clauses must be UPDATE and DELETE, and the first must have AND. At most one BY TARGET clause is permitted. The database enforces these rules; repetition alone does not and a generator need not reproduce the semantic validator. Only MERGE exposes `$action`. Its terminating semicolon is part of the definition, so runners must not strip it.
- BULK input, format and error paths are escaped string contents. `codepage` must be a documented token or code page for the OS/version; DATAFILETYPE/FORMAT/FORMATFILE options cannot be combined arbitrarily. No file/network operation is performed by this repository.
- READTEXT/WRITETEXT/UPDATETEXT are deprecated but documented SQL Server commands. `qualified_column` is a table.column reference; `text_pointer` is the documented binary pointer expression. Offset, size, insert/delete length, data type and logging restrictions remain consumer constraints. These are not substitutes for modern varchar(max)/varbinary(max) `.WRITE` syntax.

## Tables, partitions, indexes and statistics

- `partition_data_type`, `boundary_value`, `partition_number` and range endpoints follow the exact partitioning type/value rules. No duplicate boundary values, at most 14999 boundaries; target partition scheme/filegroups must exist. `filegroup` can be a properly delimited PRIMARY/default name where allowed.
- CREATE TABLE now includes common disk-table temporal/ledger columns, masking/encryption/sparse/FILESTREAM, partition storage, inline row indexes and compression. `table_index_option` is still an opaque CREATE TABLE index-option node, not the complete standalone CREATE INDEX option list. Memory-optimized and FileTable creation, inline columnstore/full key-option permutations and some computed-column constraints remain unexpanded. These are applicable SQL Server features, not excluded products.
- Temporal/ledger column type/nullability, period pairing, history-table naming and append-only/updateable ledger restrictions require semantic validation. HIDDEN is valid only for permitted generated columns. The `data_type` node remains a type declaration, not a full type/function catalog; JSON GA and single-precision vector types may be bound by consumers, but half-precision preview types are excluded from the baseline.
- ALTER TABLE adds constraints/computed columns, attributes/masks, SWITCH, tracking/triggers, period/system-versioning and basic rebuild. Memory-optimized alterations, FileTable, full online/partition rebuild/constraint options and simultaneous temporal-column ADD forms remain partial. Removed Stretch and Edge-only DATA_DELETION are not imported from shared pages.
- Graph CREATE TABLE has a separate partial definition for node/edge columns and CONNECTION constraints. Hidden pseudo-columns and graph INSERT/MATCH forms remain contextual; an ordinary table-column expression does not validate them.
- `filter_expression` is an index/statistics restricted predicate. General SELECT WHERE expressions are not interchangeable. Sample settings, AUTO_DROP, external-table statistics, incremental/filtered combinations and ALL/COLUMNS/INDEX exclusions require validation. STATS_STREAM and synthetic ROWCOUNT/PAGECOUNT options are deliberately omitted as documented unsupported/internal use, not advertised as supported user grammar.
- Index option lists must be nonconflicting and appropriate for index kind, partition scope, ONLINE, RESUMABLE and edition. Numeric ranges and compression capabilities are not enforced by SNF. DROP INDEX retains a partial modern base grammar; legacy naming and clustered move/online options remain unexpanded.
- Selective XML `node_path`/`xsd_type`/namespace values are escaped string contents; promoted names are identifiers. XPath typing, SINGLETON and MAXLENGTH legality require validation. ALTER selective XML's FOR branch cannot contain WITH options even though the official syntax summary shows both; the argument restriction wins. Use general ALTER INDEX for applicable maintenance.
- Columnstore ORDER/WITH ordering has contradictory official SQL Server summary versus examples G/H. The definition follows the examples (ORDER before WITH), is marked partial and needs explicit engine verification. This is a known source discrepancy, not a tested compatibility claim.
- JSON indexes are included as GA based on the freshly read [JSON overview](https://learn.microsoft.com/en-us/sql/relational-databases/json/json-data-sql-server?view=sql-server-ver17#sql-server-2025-changes). JSON paths must not overlap; clustering-key and column restrictions apply. DATA_COMPRESSION is excluded because the current reference's Limitations says it is unsupported despite its syntax summary listing it. Vector indexes remain preview and are not included.

## Full-text and external objects

- Full-text definitions require installed full-text components; STATISTICAL_SEMANTICS has further semantic-search/platform prerequisites. `language_term` is a valid language name/literal/LCID in that position. Stopwords are complete quoted SQL literals, optionally N-prefixed when allowed. Property GUIDs, IDs, names and descriptions obey documented types and uniqueness.
- SQL17 external sources omit retired Hadoop TYPE/RESOURCE_MANAGER_LOCATION branches. `connection_options` is an escaped connector-specific option string. Credentials are object references, never embedded secrets. Supported protocols, drivers and OS/edition prerequisites vary; not every external-table/file query requires a PolyBase service in SQL17, so installation must be checked per connector.
- External file formats include DELIMITEDTEXT, PARQUET and supported DELTA. RCFILE/ORC Hadoop formats, Edge-only JSON format and Synapse-only PARSER_VERSION are excluded. DELTA is subject to the documented Delta 1.0 limitations. Type mappings and external schemas remain opaque.
- CETAS is applicable to standalone SQL Server2022+; it is not accidentally excluded as Synapse-only. Export destinations, external writes and supported query shapes remain context-sensitive; Hadoop-only reject options are not imported.
- `file_or_binary_expression` is a documented path literal or binary literal/expression for external package content. Runtime registration does not happen in this repository. CREATE external language supports its documented parameter/environment strings; ALTER omits them because its remarks explicitly say they are unsupported. One file spec per platform, at most two; runtime installation and package-content validation are external concerns.
- EXTERNAL MODEL uses GA remote HTTPS embedding providers. `https_location`, model/API format compatibility and `json_parameters` schema are validated by the consumer/service. Local ONNX runtime/LOCAL_RUNTIME_PATH is preview and omitted. ALTER has an individual-option list whose nonempty requirement belongs to SQL semantics; CREATE requires its core properties.

All SQL/string/binary inputs must be escaped and bound by the consumer, never concatenated as unconstrained user suffixes. Statement presence does not authorize execution, external data transmission or security changes.
